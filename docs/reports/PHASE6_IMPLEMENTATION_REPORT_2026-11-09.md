**Source version:** `0.7.0-phase6-domain-engines`

## 1. Scope implemented

Phase 6 adds seven deterministic Kotlin domain libraries and a user-facing Compose hub:

- `:feature:prayer` — explicit custom solar-time profiles and high-latitude fallback handling.
- `:feature:hifz` — stable Quran/Mushaf reference model and user-rated spaced review.
- `:feature:travel` — local-timezone itinerary segment, DST gap/overlap validation and Qibla bearing.
- `:feature:halal` — ingredient uncertainty and user-reported certification evidence metadata.
- `:feature:zakat` — integer-arithmetic preview over user-confirmed figures.
- `:feature:inheritance` — jurisdiction/madhhab/family/estate intake plus confirmed provisional arithmetic only.
- `:feature:community-local` — bounded parser for local, versioned community snapshots and capture-freshness evaluation.

`:core:domain-api` defines the bounded domain workspace payload codec and hash-verified records. `:feature:domain-hub` exposes the seven tools from app navigation and saves drafts to the existing SQLCipher-protected Room database.

## 2. Persistence and migration

- `AppDatabase` is Room v7 with 28 entities.
- `MIGRATION_6_7` is additive: it creates `domain_workspace` and its two indexes. It does not drop or rebuild prior data.
- The DAO has revision compare-and-set update/delete operations and deterministic list ordering.
- `RoomDomainWorkspaceRepository` validates IDs, domain/schema/status, monotonic timestamps, payload bounds and SHA-256 before returning records; corrupted payload hashes fail closed.
- Instrumentation source covers SQLCipher create/read/list, CAS update/delete, tamper detection and migration preservation of old timeline/dense data.
- `7.json` is intentionally absent. It must be generated by actual Room KSP during a real Gradle build and reviewed; no schema snapshot was fabricated.

## 3. Domain safety and explicit limits

### Prayer

The calculation profile requires explicit latitude/longitude, IANA timezone, Fajr/Isha depression angles, Asr shadow factor and high-latitude policy. No named calculation method or location is silently selected. High-latitude night fractions use elapsed instants across DST transitions. The solar approximation has not been compared against an authoritative calculation service or scholar-selected local timetable, and no validity/fiqh ruling is produced.

### Hifz

The planner uses user-provided stable Mushaf edition/evidence keys and explicit user ratings (0–5). It does not generate Quran text, resolve the supplied verse key against an installed verified Mushaf, recognize recitation, score memorization or evaluate tajwid. The current hub schedules one reference at a time; full multi-passage plan management and source-backed lookup remain future work.

### Travel

The engine accepts explicit route places/timezones and rejects local DST gaps; ambiguous local times require an explicit UTC offset. Qibla uses explicit coordinates. It does not infer qasr/jamʿ from distance or timezone changes. No approved madhhab-specific travel ruleset is installed, so fiqh guidance remains unavailable.

### Halal

Ingredient labels and certificate metadata are evidence candidates only. A user-reported scope match is not independent verification. The engine never returns a halal/haram verdict. No authoritative certification registry, signed certifier keyring, live source verification or scholarly review integration is present.

### Zakat

The current UI covers cash and short-term liabilities only. Valuation date, nisab, rate and haul duration are manually entered. Even a below-user-entered-threshold or incomplete-haul result is labelled an unverified arithmetic preview, never a religious status. Gold/silver/trade/investment/agricultural/livestock workflows, current market valuations and approved madhhab-specific rules are not implemented.

### Inheritance

The current screen captures jurisdiction, an explicitly selected madhhab, family facts and estate amounts. The user must confirm the facts and attest that unlisted potentially relevant heir categories were described. The engine may show a provisional arithmetic remainder only; it does not implement fixed shares, exclusion rules, awl/radd, wasiyya limits or distribution. No signed jurisdiction-/madhhab-reviewed ruleset or legal/scholarly approval is available.

### Community

`TL-COMMUNITY-V1` is a bounded offline import. Source capture time is carried in the file header and separated from import time; the user must enter a staleness threshold. Source names, references and timestamps are claims in user-supplied text, not cryptographic authenticity or proof that an event is accurate. The UI lists at most 100 imported entries. No live directory, messaging, presence, remote notification, organizer identity verification or data-rights approval is included.
